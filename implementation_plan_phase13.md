# Phase 13 — Product Capabilities, Fuzzy Router & Context Depth
## Implementation Plan

---

## 1. Problem Statement & Current Limitations

### Problem 1: STT Near-Miss Transcriptions Fall Through to Ollama (P0)
- **Current Limitation**: Minor STT voice transcription variations (`"open grove"`, `"open groom"`, `"openvscode"`) miss exact regex router patterns. They pass to Ollama, causing a ~2.5s delay to return `"I didn't understand that."`
- **Solution**: Implement a fast Fuzzy Phonetic Router (`friday/intent/fuzzy_router.py`) using Levenshtein distance and target alias maps to resolve near-miss app/website targets in `< 0.5 ms` without calling Ollama.

### Problem 2: Context Resolution Deficits for Anaphora & Search Results (P0)
- **Current Limitation**: User says `"Open Chrome"`, then `"Close it"`. System fails to resolve `"it"` to `"chrome"` for `CLOSE_APP`. User says `"Search Python tutorials"`, then `"Open the first result"`. System fails because search result URLs are not indexed in `ShortTermContext`.
- **Solution**: Expand `ShortTermContext` to index search result URLs and map pronoun references (`"it"`, `"that app"`) across complementary action pairs (`OPEN_APP` -> `CLOSE_APP`).

### Problem 3: Missing Audio Barge-In Interruption (P1)
- **Current Limitation**: If user speaks while Piper TTS is outputting audio, the assistant does not interrupt audio playback.
- **Solution**: Integrate an active barge-in listener in `friday/voice/audio_input.py` that sends an emergency stop signal to `TextToSpeech.stop()` when VAD detects speech mid-synthesis.

### Problem 4: Lack of Visual Assistant Status (P1)
- **Current Limitation**: Assistant runs strictly in CLI terminal without visual feedback indicating state (`IDLE`, `LISTENING`, `THINKING`, `SPEAKING`).
- **Solution**: Implement a lightweight status engine (`friday/ui/status.py`) rendering compact status indicators.

### Problem 5: Missing Safe Desktop Window Actions (P2)
- **Current Limitation**: Assistant cannot minimize, maximize, or screenshot windows.
- **Solution**: Implement `friday/tools/desktop.py` (`MINIMIZE_APP`, `MAXIMIZE_APP`, `TAKE_SCREENSHOT`) with post-action verification.

## 3. Security Implications

- **No Shell Execution**: Zero `shell=True` and zero `os.system` across all new Phase 13 code.
- **Strict Target Whitelisting**: Fuzzy phonetic matching applies strictly against pre-defined, safe application executables (`_APP_EXECUTABLES`) and known website URLs (`_WEBSITE_URLS`). It cannot invent arbitrary target strings.
- **Safety Policy & Permissions**: All actions generated by fuzzy routing or context resolution remain 100% subject to permission gates, confirmation policy (`CLOSE_APP`), upfront plan validation, and post-action verification.
- **Fail-Closed Defaults**: `dry_run: true` and `allow_real_execution: false` in `config.yaml` remain untouched.

---

## 4. Performance & Latency Implications

- **Fuzzy Router Latency**: Target string comparison against known alias dictionary takes `< 0.5 ms`.
- **Ollama Invocations**: Reduces Ollama invocations by a further ~80% for noisy/mis-transcribed utterances.
- **Audio Barge-In**: Eliminates audio playback overhang latency when user interrupts speech.
